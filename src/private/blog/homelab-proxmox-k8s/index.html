My Homelab Blueprint: Virtualization with Proxmox, K8s, and Local LLM Inference

There is no better way to truly understand distributed computing, Linux systems administration, and computer networking than operating your own bare-metal home server cluster.

As an Information Engineering student at TUM and an active participant in local AI systems exploration, my home lab is both a testbed for software development and a computational sandbox for training and inference experiments.

The Hypervisor Layer: Proxmox VE

The backbone of the lab is built on Proxmox VE. Proxmox allows granular allocation of CPU cores, memory limits, and PCIe passthrough devices:

  • LXC Containers for Microservices: Lightweight Linux containers handle local DNS resolution (Pi-hole), local Git mirrors, and reverse proxies (Caddy/Nginx) with negligible memory overhead.
  • QEMU KVM for Isolated Testing: Full virtual machines are spun up on demand for evaluating Linux distributions, testing OpenBMC emulators (QEMU aspeed), and validating custom kernel builds.
  • PCIe GPU Passthrough: Discrete GPUs are passed directly into dedicated inference VMs running vLLM, llama.cpp, and Ollama, allowing high-throughput quantized model serving for local agent workflows.

Container Orchestration with k3s

To mirror cloud-native production environments, I run a lightweight k3s Kubernetes cluster across the nodes. This allows declarative GitOps deployments for internal tools, automated Let's Encrypt TLS certificate provisioning, and persistent storage management over local ZFS pools.

Contributing Compute to Open AI Research (Silcia)

In June 2026, I noticed discussions around Silcia, an intriguing research effort that claimed to achieve up to an 85% reduction in parameter requirements for language models under 100M parameters compared to conventional Transformer architectures.

Realizing that indie AI researchers often struggle with compute limitations, I reached out to the author and configured secure, remote access to unused GPU compute slices on my home servers. Being able to contribute tangible hardware cycles to open research on parameter efficiency was deeply rewarding and reinforced my passion for self-hosted infrastructure.
