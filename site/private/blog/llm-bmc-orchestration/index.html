Autonomous Datacenters: Bringing LLM Orchestration to Server BMCs

Published: Sep 2026 • By Tomi Yang • Tags: OpenBMC, Redfish, Datacenter, InfiniBand

In June 2026, while attending Computex in Taipei and the NVIDIA Global Developer Conference, I had the privilege of visiting Compal’s enterprise server testing facility. Walking through aisles of high-density AI servers running racks of GPUs connected by optical InfiniBand backplanes was awe-inspiring.

Yet, as I watched engineers perform qualification runs, a stark contrast emerged. While physical actions like seating accelerator cards and plugging cables must be done by humans, the vast majority of software validation procedures were manual, repetitive, and error-prone.

The Validation Bottleneck

Validating a cluster for InfiniBand bandwidth throughput requires several sequential stages:

  • Booting the machine into PXE network installers or live environments.
  • Mounting virtual ISO media via out-of-band management controllers.
  • Installing OS kernels, matching NVIDIA Open Kernel modules, and compiling Mellanox OFED drivers.
  • Running ib_write_bw and latency benchmarks across network fabrics.
  • Troubleshooting kernel panics or PCIe negotiation faults by reading Serial-over-LAN (SOL) consoles.

Every time a driver version changes or a BIOS parameter is tweaked, engineers repeat these steps manually across dozens of machines.

The Redfish + LLM Paradigm

Baseboard Management Controllers (BMCs) run specialized embedded Linux distributions (such as OpenBMC) independent of the host CPU and OS. Through standard DMTF Redfish REST APIs, nearly every hardware parameter — power cycling, virtual media mounting, thermal fan curves, and BIOS configuration registries — can be manipulated programmatically.

By connecting an LLM agent harness (similar to what we built in Cognithor) directly to Redfish endpoints and the Serial-over-LAN terminal stream, we can create an autonomous hardware technician:

  1. The agent receives a target test goal: "Validate HDR 200Gb/s InfiniBand throughput on Node 4 with Ubuntu 24.04 and kernel 6.8."
  2. The agent commands the BMC to mount the appropriate boot image, powers on the host, and monitors the boot console.
  3. If an initial driver compile fails due to a missing kernel header, the agent reads the compiler error trace from the SOL console, runs the fix in the remote shell, and resumes the benchmark script.

Open Innovation Over Closed Internships

When I demonstrated this concept to the Vice President of Compal during our lab discussion, he was immediately enthusiastic and offered me a paid internship to implement the system internally.

While tempting, I decided that the modern server ecosystem desperately needs open, standardized tooling rather than proprietary vendor silos. By maintaining this as an open-source project (OpenBMCUI), we can help data center operators and homelab enthusiasts worldwide automate their hardware lifecycle without vendor lock-in.
